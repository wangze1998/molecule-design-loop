**ArtArmAi** is the nickname of this skill; its technical name, used for installation and loading, stays `molecule-design-loop`.

Open agent skill for constraint-driven molecule and polymer design, for Claude Code and Codex. Combines the user's Zotero library with an active literature search, adversarial chemistry review, novelty checking and result-to-claim auditing, alongside RDKit filtering, visual candidate review and explicit user approval before xTB. Structures and review packets are generated by tested scripts rather than written out by the model.

## Release Track

**v0.6.0** (2026-11-20) — Selectable reviewers. Every review and search step was wired to Gemini, so when Gemini could not be reached (credits gone, licence refused, account not eligible in its region) the mandatory steps stopped or were switched without a record. New Step 0 resolves a `review` role and a `search` role from the invocation, `molecule-design-stage/reviewer.json`, a user file, or the Gemini default; `scripts/reviewer_route.py` does the resolution, refuses the executor's own model family, moves to an opt-in backup only after failures that prove nothing ran, and stops with `REVIEW_UNAVAILABLE` after a timeout. Reviewers can be separate agent sessions opened through Agent HUD, and Steps 3.5 / 9.5 allow a two-message rebuttal exchange in which the reviewer's last answer is the record. `DESIGN_LOOP_STATE.json` 1.2 records every route and attempt; `REVIEWER_SETUP.md` covers installation and a one-command check.

**v0.5.0** (2026-11-12) — Run integrity. During a run the agent could edit the skill's own scripts, thresholds and protocols, and nothing caught it until someone ran the tests. Now the skill is read-only during a run (integrity rule 9); a rule that looks wrong becomes `ROUND_N_CHANGE_REQUEST.md`, which must say which candidates the change would promote, and the user decides. New `scripts/provenance.py` hashes the skill files, the locked spec and the environment at the start of each round and verifies them before Steps 7, 11 and 12, with the snapshot pinned by its own hash; `DESIGN_LOOP_STATE.json` records both, and the report gains a *Run integrity* section. `install_molecule_design_loop.sh --read-only` adds prevention on top of detection.

**v0.4.0** (2026-11-05) — Fix: with fewer than three non-dominated candidates, `pareto_rank` handed positions 2 and 3 to dominated candidates while the report's final top set correctly excluded them, so the CSV and the report disagreed and the scoring protocol's no-dominated-in-top-3 rule was broken; the test asserted the broken numbering. `--pareto-rank-mode protocol` shifts dominated candidates past rank 3 and Step 11 uses it; the default mode keeps old rounds reproducible but now warns and names the conflict. New `--role-column` reports `role=control` rows separately so a reference compound cannot dominate every candidate.

**v0.3.1** (2026-11-04) — Fix: the Step 9.5 packet builder read the xTB results file under column names `candidate_schema.md` does not use, so a schema-conformant round file produced an evidence section with no numbers in it; the test fixture used the script's own names, which is why the suite never caught it. Schema names are now authoritative, the older spellings are accepted as aliases, and missing required columns are named rather than dropped.

**v0.3.0** (2026-11-04) — Token economy. A full round used to cost far more than the chemistry warranted, because the model hand-wrote derived columns and read whole files back. SKILL.md became a step router with explicit reading rules and handoff points; `build_candidates.py`, `build_gemini_inputs.py` and `inspect_round.py` moved the derived data, the review packets and file inspection into tested code; `test_skill_contract.py` enforces the SKILL.md line budget, live links, tested scripts and no local paths.

**v0.2.6** (2026-11-04) — The v0.2.5 ranking diagnostics become a deterministic, tested script (`scripts/ranking_diagnostics.py`): dominance, pareto/shadow ranks, concrete exclusion reasons, the Kendall τ-b matrix, and the dominated/assessed count, stdlib-only, with `--benchmark-ids` recovery of known compounds. Enforces "unknown is non-comparable, never a sentinel" in code.

**v0.2.5** (2026-11-03) — The ranking audits itself. Kendall τ-b redundancy matrix over the five ranking axes (τ-b, not Pearson — the axes are ordinal with heavy ties), mandatory `candidates_dominated / candidates_assessed` reporting so a dominance criterion that dominated nothing cannot pass as a working gate, and a property-only `shadow_rank_property_only` ablation naming every candidate the practicality constraint excluded and why.

**v0.2.4** (2026-08-21) — The loop must now say what it does *not* know. Claim audit triggers on un-evidenceable objectives (affinity, potency, selectivity, self-assembly…) even when xTB never ran, emitting `no_direct_evidence`. New `loop_calibration` block tracks promoted-vs-worked and prediction-vs-outcome, reported honestly in `DESIGN_REPORT.md`.

**v0.2.3** (2026-08-10) — Synthesis practicality became multi-objective and enforcing: new `overall_yield_estimate` and `hazard_toxicity_flag` gate columns, optional `route_alternatives` trade-off profile, and Step 11 ranking by Pareto *dominance* over {property fit, cost, time, yield, hazard} instead of a tiebreak. ## Why this repo exists

Many "LLM for molecule design" workflows fail in predictable ways:

- they generate molecules without grounding them in the field's known scaffolds and SAR
- they let the same model that designed a candidate also score it — no adversarial check
- they push xTB numbers into design conclusions without auditing what the numbers actually prove
- they spend most of their budget on the model retyping data a script could derive

`molecule-design-loop` is a structured loop against those failure modes.

## Scripts

Every script takes `--help`, writes to a file you name, and has tests next to it.

| Script | Purpose | Needs |
|---|---|---|
| `build_candidates.py` | one YAML config → `ROUND_N_CANDIDATES.csv`, deriving the SMILES copies, formula, atom indices and repeat-unit drawings, and refusing a structure that does not parse, leaves the allowed elements, carries a charge, or misses its declared motif counts | RDKit, PyYAML |
| `rdkit_filter_candidates.py` | descriptors, medchem triage, forbidden-SMARTS filtering | RDKit |
| `render_candidate_gallery.py` | filtered CSV → standalone HTML gallery | RDKit |
| `build_gemini_inputs.py` | round files → Step 3.5 / 5.5 / 9.5 review packets | stdlib |
| `ranking_diagnostics.py` | dominance, Pareto and shadow ranks, Kendall τ-b matrix | stdlib |
| `inspect_round.py` | bounded views of a round file: `summary`, `cols`, `row`, `grep`, `check`, `html` | stdlib |
| `provenance.py` | `snapshot` / `verify` / `diff` the skill files, locked spec and environment a round ran on; names every changed file | stdlib |
| `reviewer_route.py` | pick the reviewer and search backend (Gemini, Codex, Antigravity, DeepSeek, manual; direct or through Agent HUD), with safe fallback and an independence check | stdlib |

Start from [`examples/example_candidates_config.yaml`](examples/example_candidates_config.yaml):

```bash
python3 molecule-design-loop/scripts/build_candidates.py \
  --config examples/example_candidates_config.yaml --check-only
```

Run the tests with:

```bash
python3 -m pytest molecule-design-loop/scripts
```

## What the skill does

**Structure image input** (Step 0.5): Users can provide journal figures, ChemDraw screenshots, or hand-drawn sketches instead of typing SMILES. Claude extracts structures directly from images, validates with RDKit, and feeds confirmed seeds into the design spec.

**Literature intelligence**: Zotero personal library (Steps 1.5-A) and active field search (Step 1.5-B) run in parallel. Both are mandatory. `LIT_PACKET.md` merges the two streams; contradictions are flagged, not silently resolved.

**Candidate generation**: Every proposal must trace to a scaffold, SAR rule, or design principle from `LIT_PACKET.md`. Unsourced exploratory candidates are capped at 10% of each round.

**Adversarial review** (Step 3.5): Gemini reads the raw candidate CSV with a chemistry-skeptic prompt before RDKit filtering. Challenges each candidate's design logic, synthesis plausibility, and expected proxy effect. Claude does not review its own candidates.

**Deterministic triage** (Step 4): RDKit validity, MW/logP/TPSA, PAINS/Brenk alerts, Murcko scaffold deduplication. Synthesis feasibility gate (Step 5) requires a plausible make/buy route before gallery promotion.

**Novelty check** (Step 5.5): `prior_art_search` flags already-reported structures before the visual gallery. `known` candidates are automatically demoted to control role.

**Human-in-the-loop** (Step 6–7): RDKit-rendered HTML gallery with structure depictions, filter decisions, and design rationale. Explicit user approval required before any xTB run.

**Result-to-claim audit** (Step 9.5): After xTB, Gemini maps each computed number to exactly what it proves and what it cannot prove. `overclaim` flag blocks a score ≥ 4 in Step 11.

**NMR prediction and verification** (Step 9.7, optional): Claude predicts 1H/13C NMR spectra for top candidates using its internal chemistry knowledge. When experimental NMR data is available, a predicted-vs-experimental comparison produces a structural verification status. Based on Anthropic's "Making Claude a Chemist" research (±0.079 ppm 1H accuracy).

**Iterative scoring** (Step 11): Gemini reads design spec + adversarial review + novelty check + claim audit + NMR verification in a fresh thread. Pareto ranking across hard-constraint pass, synthesis feasibility, evidence level, and soft preferences.

**Ranking diagnostics** (Step 11): the ranking cannot audit itself, so two checks do. An axis-redundancy matrix (Kendall τ-b) asks whether the five ranking axes carry independent information or whether the trade-off is narrower than it looks, and reports how many candidates were actually dominated — if none were, the practicality gate did not bind and the round says so. A practicality ablation re-ranks on property fit alone and names every high-scoring candidate the constraint kept off the bench, with the concrete values responsible. Both are reported even when the answer is "practicality changed nothing".

Both small-molecule and polymer/material design are supported. Polymer candidates use finite capped oligomers for RDKit/xTB; polymer-level properties that cannot be inferred from surrogates are listed as non-xTB targets.

## Workflow

```text
[structure images → IMAGE_EXTRACTED_SMILES.csv]       ← Step 0.5 (optional)
→ design_spec.md
→ [Zotero extraction (1.5-A) || active search (1.5-B)]  ← parallel
→ LIT_PACKET.md (merged)
→ ROUND_N_CANDIDATES.csv
→ ROUND_N_GEMINI_ADVERSARIAL_REVIEW.md              ← Step 3.5
→ ROUND_N_FILTERED.csv (RDKit)
→ ROUND_N_SYNTHESIS_FEASIBILITY.csv
→ ROUND_N_NOVELTY_CHECK.md                           ← Step 5.5
→ ROUND_N_CANDIDATE_GALLERY.html
→ user approval checkpoint                           ← mandatory
→ ROUND_N_XTB_RESULTS.csv
→ ROUND_N_CLAIM_AUDIT.md                             ← Step 9.5
→ ROUND_N_NMR_PREDICTIONS.csv                       ← Step 9.7 (optional)
→ ROUND_N_DECISION.md (Gemini + Pareto)
→ next round or DESIGN_REPORT.md
```

## Quick Start

Install the main skill:

```bash
bash install_molecule_design_loop.sh
```

Install the main skill plus the optional literature helper:

```bash
bash install_molecule_design_loop.sh --install-research-lit
```

Install the skill read-only, so a design run cannot edit the rules it is judged by (re-running the installer replaces it; see [`references/run-integrity-protocol.md`](molecule-design-loop/references/run-integrity-protocol.md)):

```bash
bash install_molecule_design_loop.sh --read-only
```

Invoke the skill in Codex:

```text
/molecule-design-loop "/path/to/design_spec.md"
```

Example input files:

- [`examples/example_design_spec.md`](examples/example_design_spec.md)
- [`molecule-design-loop/templates/design_spec_template.md`](molecule-design-loop/templates/design_spec_template.md)

Default install target:

```text
$CODEX_HOME/skills/molecule-design-loop
```

Fallback when `CODEX_HOME` is unset:

```text
~/.codex/skills/molecule-design-loop
```

## Design Principles

- Constraints first, novelty second
- xTB is evidence, not the final decision-maker
- Human structural review happens before xTB
- Rejected candidates and rejection reasons are kept for later refinement
- Candidate rounds should test interpretable design moves, not near-duplicate noise

## Requirements

- Codex with access to a local skills directory
- Python 3
- RDKit installed in the Python environment

Optional:

- xTB for the quantum-screening stage
- `research-lit` as a companion literature skill
- `gemini-research` / `gemini-review` MCP (the default reviewer and search backend)
- any other reviewer: Codex MCP, Antigravity MCP, the Agent HUD MCP (opens a Codex,
  Antigravity or DeepSeek session as reviewer), or `manual`

### Choosing a reviewer

Put a standing choice in `~/.config/molecule-design-loop/reviewer.json`, a project's
choice in `molecule-design-stage/reviewer.json`, or pass `-- reviewer: …` for one run:

```json
{"review": {"backend": "codex", "via": "agent-hud"},
 "search": {"backend": "gemini"},
 "fallback": ["deepseek@agent-hud", "manual"]}
```

The executor's own model family is never accepted as reviewer, and a review is never
switched to another provider after it may have run. Install and check each backend
with **[REVIEWER_SETUP.md](REVIEWER_SETUP.md)**; the rules are in
[`reviewer-selection-protocol.md`](molecule-design-loop/references/reviewer-selection-protocol.md).
